11  Spatial Interaction: Vector-Raster

In this chapter, we explore how vector and raster datasets can work together in spatial analysis.

First, we learn how to crop a raster so that it matches the geographic extent of a vector dataset. This allows us to focus only on the area we need.

Next, we learn how to extract raster values using point and polygon features. Raster extraction means retrieving the values stored in raster cells at locations defined by vector features.

Raster extraction works differently for points and polygons:

Points

For each point, the software finds the raster cell that contains that point and assigns that cell’s value to the point

Polygons

For each polygon, the software finds all raster cells that fall inside or overlap the polygon and returns the values from those cells

Visual representation of raster data extraction

In the figure, the raster is represented as a grid of cells, and each cell contains a value shown at its center. In the point example, there are three points placed on top of the raster.

To extract raster values to points, we identify the cell that contains each point and assign that cell’s value to the point. In this example, Point 1, Point 2, and Point 3 receive the values 50, 4, and 54, respectively.

In the polygon example, a polygon is overlaid on top of the raster cells, and the centroids of the cells are shown as black dots. Extracting raster values to a polygon means identifying the raster cells that intersect the polygon and retrieving the values of those cells. Some cells are completely inside the polygon, while others only partially overlap it.

Depending on the function and options used, different cells may be considered part of the polygon extraction. For example, by default, terra::extract() returns the values of cells whose centroids fall inside the polygon. However, it is also possible to include cells that are only partially intersected by the polygon. In those cases, we can calculate the fraction of each cell that overlaps the polygon, which is useful for computing area-weighted values later.

The prism package provides a convenient way to download and import high-resolution climate data directly into R.

To begin, you first set a local working directory where the data will be stored using options(prism.path = "your/folder/path"), and then ensure that this folder exists. In other words, options() is a convenient way to tell the package: “use this folder as the default PRISM data directory”

You can download data using functions such as get_prism_dailys() (for daily variables like precipitation or temperature) by specifying the variable type (e.g., “tmax” for max temperature), the date of interest, and whether to keep the downloaded zip file. Once the data are downloaded, PRISM automatically organizes them into a folder named according to the variable, region, resolution, and date.

To import the raster into R for analysis, you can use the terra function rast() and point it to the .bil file inside the downloaded folder. This converts the PRISM dataset into a usable raster object that can be mapped, analyzed, or combined with other spatial data.

11.2 Cropping to the Area of Interest

Here we use PRISM maximum temperature (tmax) data as a raster dataset and Tennessee county boundaries as a vector dataset.

We get TN county border data from the tigris package:

Code 
tn_co <- counties(state = "TN", cb = TRUE)

class(tn_co)

## transform using the CRS of the PRISM tmax data
tn_co <- st_transform(tn_co, terra::crs(prism.tmax))

The terra::crop() function trims a raster to the geographic extent of another spatial object. In this example, terra::crop(prism.tmax, tn_co) cuts the prism.tmax raster so that it keeps only the area covering the extent of tn_co.

This is useful for reducing file size, speeding up analysis, and focusing only on the study area.

Code 
# Cropping 
tmax_crop <- terra::crop(prism.tmax, tn_co)

tm_shape(tmax_crop) +
  tm_raster()

terra::crop(prism.tmax, tn_co) uses the extent of tn_co, which is its bounding box.

That means the raster is trimmed to the smallest rectangle that contains tn_co, not to the exact county boundaries. So cells outside the county polygons but still inside that rectangle will remain.

If you want the raster to match the actual shape of tn_co, you usually follow crop() with mask():

Code 
tmax_mask <- terra::mask(tmax_crop, tn_co)

tm_shape(tmax_mask) +
  tm_raster()
Code 
# using ggplot()
ggplot() +

11.3 Extracting values from Raster layers to Vector Data

In this section, we will learn how to extract information from raster layers for spatial units represented as vector data (points and polygons).

11.3.1 Extracting to points

Let’s create our point data as the centroids of each county in TN.

Code 
tn_point <- st_centroid(tn_co)
Warning: st_centroid assumes attributes are constant over geometries
Code 
tm_shape(tn_co) +
  tm_polygons(fill = "white") + 
  tm_shape(tn_point) +
  tm_dots(fill = "blue")

We can extract values from raster layers to points using terra::extract(). It finds which raster cell each of the points is located within and assigns the value of the cell to the point.

Code 
tmax_points <- terra::extract(tmax_crop, tn_point)
head(tmax_points)
  ID prism_tmax_us_25m_20250629
1  1                    33.5542
2  2                    31.0596
3  3                    28.2538
4  4                    33.5878
5  5                    29.5014
6  6                    31.2475

The resulting object is a data.frame, where the ID variable represents the order of the observations in the points data and the second column represents that values extracted for the points from the raster cells. So, you can assign the extracted values as a new variable of the points data as follows:

Code 
tn_point$prism_tmax_us_25m_20250629 <- tmax_points[, -1]
